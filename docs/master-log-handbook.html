01The one rule

Nobody types a new task into the Master sheet.

Master is written by the system, one of two ways: the web form for a single task, or Tracker Options → Bulk Add Tasks for a batch.

This is not housekeeping. Typing straight into Master is what produced twelve task IDs that each pointed at two different pieces of work. When that happens, a developer changing their own task's status silently overwrites somebody else's row instead — the lookup finds the first match and stops.

If a cell refuses your edit

That is the protection working, not a fault. Everything except Status, Developer Remark and SVN Committed is written by the system.

02Submit one task

Open the web form, fill it, submit. Fields marked with a red asterisk are required.

  • Attachments — drag files in or click the box. 5 MB each. The Submit button greys out while files are still being read; wait for it.
  • Additional links — paste screenshots directly with Ctrl+V, or paste links as text.
  • You get the task ID back on success.
Failure is loud now

A red message means nothing was written, and everything you typed is still on the form. Fix what it names and submit again.

The old build returned a plain string on error, so every failure arrived as a success — green tick, form cleared, task never saved. That is gone.

03From IDE to task row

This is the point of the whole thing. You finish work in Antigravity or Claude Code; the session notes become a task row without retyping.

  1. Open the panel

    On the form, click ⚡ Auto-fill from AI, then Copy AI Prompt.

  2. Feed your AI

    Paste the prompt, then your raw session notes where it says [PASTE YOUR SESSION NOTES HERE].

  3. Copy the line

    The AI replies with one long tab-separated line.

  4. Paste it back

    Drop it into the box. The form fills itself.

Reading the result

OutlineMeaning
GreenAccepted
RedThe AI produced a value that is not in the dropdown — fix it by hand
NoneColumn was empty

The message below the box lists every problem at once, and your paste stays in the box when it fails, so you can see what actually arrived.

The prompt writes itself

It is generated from the live configuration, so the team list and module list inside it always match the dropdowns. When somebody joins or leaves, the prompt updates itself. Do not keep an old copy in a text file — copy it fresh each time.

Language the COO can read

Task Summary and Remarks are read by management, who do not know our shorthand. The prompt bans planning codes — AC-082, V64, D-C22.1, B305, Q7 — and makes the AI translate them into what they do.

The one exception

Client comment numbers come from the client's own document and must be spelled out in full: “(Client Comment 24)”, never C24.

Developer Remark is for you and the next developer. Real file names, tables, endpoints and functions belong there. Planning codes still do not.

04Bulk add

A work session usually produces several tasks. Ask your AI for one line per task, newline separated, then Tracker Options → Bulk Add Tasks.

[AUTO]→09/08/2026→Fix contact person edit losing address fields→Prathap Valuers→Valuation ERP→Bug-Core→→Venul→…
[AUTO]→09/08/2026→Reschedule modal wipes the follow-up date→Prathap Valuers→Valuation ERP→Bug-Core→→Venul→…

→ marks a real tab character. If your AI sends spaces instead, the check will say so.

Check before you import

Press Check rows first. Nothing is written yet. Every row gets a verdict:

VerdictMeaning
ReadyWill import as-is
WarningWill import, but read the note — usually an internal code that slipped into the summary, or a missing assignee defaulted to Unassigned
BlockedWill not import. Fix it
All or nothing

Import stays locked while any row is Blocked, so you never end up with half a batch in Master. On success you get the ID range that was created — TASK-2460 … TASK-2472.

Edit the box after checking and Import locks again. That stops you importing something different from what you reviewed.

05Working your tasks

Two ways in. Same data, same buttons.

  • Inside the spreadsheet — Tracker Options → Open Task Dashboard.
  • On the web — add ?page=mytasks to the web app URL. No spreadsheet needed. Use this one if you never open the sheet.

The cards

  • The colour bar on the left — grey New, green Active, orange Paused, blue Done, purple Blocked, red Overdue.
  • The counters across the top are filters. Click one.
  • Search matches summary, client or task ID.
  • The time chip shows total logged. A green dot means the clock is running right now, and it ticks while you watch.
ButtonWhat happens
StartStatus → In Progress, clock starts
PauseClock stops, elapsed time is added to the total
DoneClock stops, time banked, completion date and time stamped

Time accumulates across sessions. Start / Pause all day; the total keeps adding up. Pausing never resets it.

Tick several cards and the dark bar at the top will Start, Pause or Done all of them at once.

06Editing on the sheet

You can still work from the tabs. What syncs depends entirely on which tab you are standing on — this catches people out.

You editWhat happens
Your own tabSyncs up to Master. Status starts and stops the timer. Works as intended.
MasterStatus changes do not sync down and do not run the timer. Only the Assigned column does anything — it moves the task to the new person's tab.
Another person's tabSyncs to Master exactly as if it were yours. There is no ownership check.
KPI, DB, Bug Count, any other tabNothing. Ignored entirely.
Change status on your own tab, or in the dashboard

Doing it on Master looks like it worked — the cell changes — but no timer runs and the team tab still shows the old value.

The dashboard ignores which tab you are on. It always reads Master and filters by your email, so opening it from someone else's tab still shows your own tasks.

07The Admin menu

Under Tracker Options. These change the sheet for everybody.

ItemWhat it does
Lock SheetsProtects Master completely. On team tabs, leaves only Status, Developer Remark and SVN Committed editable. Refreshes the dropdowns at the same time.
Unlock SheetsRemoves only the protections this script created. Anything you protected by hand is left alone.
Refresh DropdownsRe-applies Status, SVN and Assigned validation across every task sheet. Run it after adding or removing someone.
Configure WebhookStores the tunnel URL and shared secret in Script Properties — never in the source, so a sheet viewer cannot read them.
Send Latest Task to TerminalPushes the newest task ID to your local listener so an IDE session can pick it up.
Known gap

The menu is visible to everyone who can open the sheet. Anyone can click Unlock Sheets and undo the protection, and anyone can edit anyone else's tab. There are no permission checks in the code — access is whatever Google Sheet sharing allows.

08IDE connection

The tracker exposes a small MCP server so your IDE can read the sheet directly — the next free task number, your open tasks, one task by ID.

All three clients read their config only at startup. After editing, quit the client fully — closing the window is not enough for Claude Desktop, quit it from the system tray.

Antigravity / Gemini

Numbering

The MCP can reserve a block of IDs. The form allocates from the highest number that exists in the sheet, so a reserved-but-unwritten ID will be handed out twice. Write reserved rows promptly, or do not reserve.

Full detail, including the smoke test and what to do on another machine, is in automation/RUNBOOK.md.

Never reuse a gap

Missing numbers in the sequence are deleted tasks. Something somewhere may still reference that ID. Always take the next free number, never fill a hole.
