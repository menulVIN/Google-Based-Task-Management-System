# Task Tracker — Apps Script source

This folder is the source of truth. The Apps Script editor holds a *copy*.
Edit here, paste into the editor, save. Never edit only in the editor — that copy
is not backed up anywhere, and until now the entire system existed nowhere else.

Web app (dev): https://script.google.com/macros/s/AKfycbwHRttdAdRoQuBXJOw9JBDZoGhGgtN-UKc0MrrpdPk/dev

## Files

| File | Apps Script name | Purpose |
|---|---|---|
| `Code.gs` | `Code.gs` | All backend logic |
| `Index.html` | `Index` | Task submission form (web app default page) |
| `Sidebar.html` | `Sidebar` | Dashboard inside the spreadsheet |
| `MyTasks.html` | `MyTasks` | Dashboard on the web, no spreadsheet needed |
| `DashboardStyles.html` | `DashboardStyles` | Shared CSS for both dashboards |
| `DashboardBody.html` | `DashboardBody` | Shared markup + JS for both dashboards |
| `BulkAdd.html` | `BulkAdd` | Bulk paste dialog |

`Sidebar` and `MyTasks` pull in the two shared partials via `include()`, so the
dashboard is written once and rendered in two places. Change `DashboardBody`
and both update.

## Deploying

1. Open the spreadsheet → **Extensions → Apps Script**.
2. Create the file names in the table above (⊕ → HTML / Script). Names must match exactly, no `.html` suffix inside the editor.
3. Paste each file's contents. Save.
4. Reload the spreadsheet. The **Tracker Options** menu appears.
5. First menu click triggers the Google authorisation prompt → *Advanced* → *Go to project* → *Allow*.
6. **Deploy → Manage deployments → edit → New version → Deploy** so the web app picks up the HTML changes. Skipping this leaves the old form live.

## Triggers

`onEdit` is a simple trigger and needs no setup.

`moveRowOnAssignment` needs an **installable** trigger, otherwise reassigning a
task on Master will not move it between team tabs:

**Triggers** (clock icon) → **Add trigger** → function `moveRowOnAssignment`,
event source *From spreadsheet*, event type *On edit*.

## Configuration

Everything tunable sits at the top of `Code.gs`:

- `DEV_EMAILS` / `DEVELOPER_SHEET_NAMES` — the active team. Each name needs a matching tab.
- `ARCHIVED_DEVELOPER_SHEETS` — people who have left. Tabs kept so history stays readable; they never appear in an assignment dropdown.
- `MANAGER_EMAILS` — sees every task and gets the team filter.
- `SHEET_EDITABLE_COLUMNS` — which columns stay hand-editable after locking. Currently 14 (Status), 18 (Developer Remark), 22 (SVN Committed).
- `ALLOWED` — every dropdown list. The sheet validation, the web form and the AI prompt all read from here, so they cannot drift apart.

### Adding a team member

1. Add name + email to `DEV_EMAILS`.
2. Add the name to `DEVELOPER_SHEET_NAMES`. Save, reload.
3. **Admin → Add Team Member Tab** — copies Master's 23 headers verbatim.
4. **Admin → Check Sheet Alignment** to confirm.

Never type the headers by hand or have an AI generate them from a typed list.
Master is 23 columns; a list one short shifts every column after the gap, and
`onEdit` reads header names from *Master*, not from the tab being edited, so the
shift writes to the wrong column instead of failing. Full detail in
`docs/ADDING-PEOPLE.md`.

### Removing one

Move the name from `DEVELOPER_SHEET_NAMES` into `ARCHIVED_DEVELOPER_SHEETS` and
drop it from `DEV_EMAILS`. Do **not** delete the tab — their history lives there
and stays filterable in the dashboard.

## What changed from the previous build

| Was | Now |
|---|---|
| `processForm` returned the string `'Error: …'`, so `withSuccessHandler` fired and every failure showed a green tick while the form reset and lost the user's input | Returns `{success, taskId \| error}`; the form keeps your entries and says what went wrong |
| `getNextTaskNumber` threw whenever the bottom row disagreed with the highest ID — which hard-blocked every submission for the whole window after the 2026-09-03 duplicate repair | Always allocates `max + 1`, logs the gap, throws only when column A holds no valid ID at all |
| Developer Remarks was generated by the AI, parsed past, and written as `undefined` | Real field on the form, mapped from column 18, saved |
| Paste box was `<input>` — could not hold a newline, so the fence-stripping and header-dropping guards were dead code | `<textarea>` bound to `paste`, reading `clipboardData` |
| Auto-fill fired on every keystroke and wiped the box on error | Fires once per paste; the box keeps its content when validation fails |
| `new Date(...).toISOString()` moved every `mm/dd/yyyy` deadline back one day in UTC+5:30 | Explicit format parsing plus local-component formatting |
| Card summaries interpolated into `innerHTML` — a quote or `<` broke the layout | Built as DOM nodes with `textContent` |
| `bulkUpdateStatusFromSidebar` took and released the script lock once *per task* | One lock for the whole batch |
| `findMasterRowById` scanned 2,400+ rows in JavaScript on every call | `createTextFinder` scoped to column A |
| Pause/Done read the running total with `parseFloat` on a duration cell, which returns `NaN` for a Date | Normalised through `toDayFraction_` first |
| Attachments were set to `ANYONE_WITH_LINK` — client screenshots public to anyone with the URL | `DOMAIN_WITH_LINK`, falling back only if the account has no domain |
| Failed uploads returned `null` silently and the attachment vanished | Reported back to the user by filename |
| `DEV_EMAILS.Unassigned` pointed at `admin_or_team_lead_email@example.com` | Points at a real inbox |
| Menu told users to click "Configure Claude Webhook", which did not exist in the menu | Present under **Admin** |
| Every `<label>` got a red asterisk, including "Deadline Time (Optional)" | Only `label.required` |
| Summary, remarks and issue type had no `required` attribute | Required |
| Submitting during a multi-file drop could send a short attachment list | Submit disabled until every `FileReader` finishes |
| No way to add many tasks except typing into Master by hand — the exact path that produced the twelve duplicate IDs | **Bulk Add Tasks** validates a whole paste, then commits under one lock with one batched write |
| Nothing stopped anyone typing over an automated column | **Admin → Lock Sheets** |
